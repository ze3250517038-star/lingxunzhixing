# 岭讯知行

校园办事通知核验与任务清单系统。本地原型依据挑战杯申报书 B3 的流程实现，可体验学生端与维护端。校方通知是去标识节选和字段标注，网上办理以校方原通知为准。

当前版本在原有规则抽取基础上增加了可选的 OpenAI-compatible LLM 混合抽取、字段级证据充分性门禁、网页/本地文件导入、字段级变更影响分析、按账号保存的个人课程表和可复现评测工具。LLM 未配置时不会伪造调用结果，而是回退规则模式并明确标记 `RULE_FALLBACK`。

## 本地运行

需要 Java 17、Maven 3.9、Node.js 和 pnpm。先构建前端，再把它与后端一起打包。

```powershell
pnpm --dir frontend install --frozen-lockfile
pnpm --dir frontend build
mvn -f backend/pom.xml package
java -jar backend/target/lingxun-0.1.0.jar --spring.profiles.active=demo
```

打开 http://127.0.0.1:8096/。默认配置是 `mysql`，不显式指定数据库会拒绝启动；本地演示必须加 `--spring.profiles.active=demo`，使用 H2 内存数据库，重启还原两份样本和演示账户。首页按钮可在学生端和维护端之间切换。

## 智能抽取与来源导入

维护端「通知录入」支持三种接入方式：

- 直接粘贴正文；
- 填写 `https://` 学校通知链接后点击「从链接抓取网页正文」。服务端只抓取公开静态页面，拒绝 localhost、回环、私网地址，限制 2 MB 和 15 秒超时，不执行页面脚本；动态渲染页面可能抓不到正文，此时应改用粘贴或文件。
- 上传 `txt/md/html/docx/pdf`。DOCX 使用标准 Zip + 安全 XML 解析读取段落；PDF 只提取文字层，扫描件没有文字层时会明确提示。服务端限制上传 8 MB、正文 40000 字。

抽取方式可选：

| 模式 | 行为 |
| --- | --- |
| `RULE` | 只运行本地规则，结果来源标记为规则 |
| `HYBRID` | 规则结果始终保留；LLM 只补充字段或暴露冲突；同字段不同值进入待复核 |
| `LLM` | 优先请求模型；模型不可用、无 Key、超时、HTTP 错误或正文超限时回退规则，并标记 `RULE_FALLBACK` |

LLM 配置全部来自运行环境，源码和前端不保存 Key。默认提供商为 DeepSeek 的 OpenAI-compatible 接口：

```powershell
$env:LINGXUN_LLM_ENABLED='true'
$env:LINGXUN_LLM_BASE_URL='https://api.deepseek.com'
$env:LINGXUN_LLM_MODEL='deepseek-chat'
$env:LINGXUN_LLM_API_KEY='<在本机设置，不要提交到仓库>'
$env:LINGXUN_LLM_TIMEOUT_SECONDS='20'
```

也可以替换为其他 OpenAI-compatible 服务，只需改 `base-url` 和 `model`。没有 Key 时演示仍可正常运行，界面会显示“已回退规则”。

每个候选字段绑定来源版本、原文片段和字符区间；服务端会重新回切原文验证，不信任模型返回的 offset。只有证据充分性为 `SUFFICIENT` 的字段才能人工确认和发布；日期缺年份、多日期冲突、暂定/待定、条件值“另行通知”等都会阻止自动确认。证据判断和人工修正说明可在字段、证据弹窗和审核记录中查看。

## 变更与待办

同一事项的新版本发布后，系统按字段比较上一版已确认值和当前版已确认值，区分 `继承`、`覆盖`、`冲突`、`无法判断`、`新增`，并在版本详情展示受影响角色和受影响的学生截止待办数量。有争议或未确认的截止日期不会作为有效截止日期：待办进入 `REVIEW` 时 `dueAt` 为空，日历和 ICS 导出也不会出现旧日期或新日期，直到学生确认新版本。重复发布当前版本是幂等的；并行发布由事务和事项行锁保证只有一个成功。

## 试用流程

1. 进入学生端，先看首页概览和最近截止；再到「事项查询」筛选学分申报。分别核对学生申报、学院审核、学校终审，并打开截止、适用对象、材料或入口的证据片段。订阅后打开「我的待办」。
2. 切到维护端，在「通知录入」载入竞赛改期样例，点击「归档并生成候选」。在「核验与版本」对照原文，逐项确认继承或覆盖。候选不准确时用「修正字段」，漏提取时用「补录字段」。选择本版本的证据片段，核对字段值并填核验说明。对原文仍标注暂定的决赛时间，选择「保留待复核」。字段确实不适用时选择「不适用」，已发布后关联待办会转为「不适用」，从日历中移除，也不再计入待办理。
3. 发布后切回学生端，在「我的待办」查看原日期和新日期的依据。确认新版本后，按办理清单依次完成阅读原文、确认条件、准备材料、报名或提交；勾选状态会保存在服务端。首页「今天先做」和「提醒中心」会把最紧急的事项前置。
4. 用冲突样例再走一遍。为存在两个日期的报名截止字段选择「保留待复核」后发布，学生端暂停该待办，待维护者核定有效版本后再确认。
5. 在学生端提交纠错反馈，并在「我的反馈」查看是否已核查。维护端可以关联原事项录入更正版本，并在「审核记录」查看发布前后值和操作时间。

样本来源：[创新创业实践学分通知](https://www.sgu.edu.cn/info/1065/123181.htm) · [化学实验室安全知识竞赛通知](https://www.sgu.edu.cn/info/1065/126441.htm)。补充通知样例均带模拟标记。

## 学生端功能

- **首页概览**：待办理、7 天内到期、已逾期、待复核四张卡片；新增「今天上什么」和「今天要交什么」，把当天课程与当天截止并排展示。「今天先做」按“待复核 → 已逾期 → 今天截止 → 3 天内”排序，直接给出下一步要勾选的清单项。
- **我的课表**：按学生账号保存周课表，支持添加、编辑、删除课程；可设置学期名称、开始日期和结束日期，课程可按每周、单周、双周排课。周视图按 08:00–20:00 时间轴展示，自动标记今天、当前时间和当前周次内的时间冲突，冲突课程并排显示；单双周课程按学期第 N 周过滤，单周与双周同段不会误报冲突。首页只读取当天实际会出现的课程，不参与通知核验，也不会改变待办日期。可参考 `docs/课程表-学期与单双周.md`。
- **事项查询**：关键词搜索之外增加类型筛选，列表显示当前版本和是否已订阅；详情保留原文依据、办理阶段、条件和订阅入口。
- **我的待办**：按状态、时间范围（全部/紧急/已逾期/7 天内/今天）和关键词筛选，支持按截止日或最近变更排序；每条待办显示剩余天数或逾期天数。
- **办理清单**：每个待办根据当前通知生成可勾选步骤，包括阅读原通知、确认适用对象、准备材料、完成报名或提交、截止前完成；勾选状态按用户和待办持久化，通知出新版本后旧清单自动失效，需重新确认。
- **截止日历**：月历上标出待办理和待复核的截止日期，点击日期查看当天事项；新增「已逾期」区块和「未来 14 天」议程，打开时自动定位到最近一个截止日期。日历导出仍在待办页。
- **提醒中心**：按截止日自动生成已逾期、今天截止、3 天内和本周内提醒，可跳转到对应待办或本次忽略；忽略状态仅保存在当前账号的本机浏览器，不影响其他设备。
- **我的订阅**：集中查看已订阅事项，可进入详情或取消订阅；取消订阅会删除该事项下自己的待办和办理清单，不影响其他学生。
- **我的反馈**：查看自己提交过的纠错、提交时间和维护者是否已核查，并可回到对应事项。

## 日期与人工核验

- 支持中文完整日期、同月简写和明确的跨年范围。例如，2026 年 12 月发布的「12月28日至1月5日」结束于 2027 年 1 月 5 日。截止字段取区间结束，初赛、决赛的时间字段保留区间两端。
- 日期缺少年份且仅凭发布日期无法确定、原文列出多个可能日期、区间不完整或日期不合法时，候选会保留证据和待核验原因。维护者可根据归档原文修正或保留待复核。待复核的截止日期不会成为新的待办理日期。
- 保存人工修正前，服务端验证字段类型及值，并从本版本快照按选中的字符区间取得证据。截止日期早于通知日期会在保存或发布时被拦截。原值、修正值、证据和核验说明可在「审核记录」查看。

## 核验与日历实现

- 「核验与版本」可以逐行对照两版归档正文，查看旧版独有、新版独有和共有内容。继承、覆盖及冲突仍由维护者逐项核验。使用 [JsDiff](https://github.com/kpdecker/jsdiff) 的 `diffLines`。
- 「我的待办」的状态分层和分组交互借鉴 [Nextcloud Tasks](https://github.com/nextcloud/tasks)；首页与月历入口见上文“学生端功能”。
- 「导出待办理日历」读取本人当前已核验、已确认版本的待办理日期并生成 `.ics` 文件。只写明日期的事项以全天事件导出，有明确时间的按北京时间换算。改期后请重新导出并更新日历中的旧记录。日历生成使用 [iCal4j](https://github.com/ical4j/ical4j)。

## 技术结构

- `frontend` 使用 Vue 3，按角色显示事项、证据、待办、办理清单、提醒、个人课表和维护界面。提醒中心使用浏览器 `localStorage` 保存“本次忽略”，不改动服务端数据；课表通过 `GET/POST/PUT/DELETE /api/timetable` 与后端同步，学期通过 `GET/PUT /api/timetable/semester` 保存。
- `backend` 使用 Java 17 和 Spring Boot 提供 REST 接口。通知按版本留存快照及哈希，规则匹配生成候选。人工确认前检查证据归属、片段号和字符区间。课程表按登录学生隔离，服务端校验课程名称、星期、时间顺序、颜色和单双周枚举，写操作要求 CSRF 令牌；学期起止日期由服务端校验，前端按周次过滤课程并只在当前周次检测冲突。
- 发布事务锁定事项并核对基准版本，切换当前版本后同步相关待办和审核记录。重复发布同一当前版本可以安全重试。
- 数据库表结构在 `backend/src/main/resources/schema.sql`。通知字段及其证据作为版本快照的一部分保存，订阅、待办、办理清单、反馈、记录、个人课程和学期设置分别落表。办理清单勾选通过 `PATCH /api/todos/{id}/steps/{stepKey}` 保存，按当前通知版本校验，新版本发布后自动失效。

## 切换到 MySQL

创建 `utf8mb4` 编码的 `lingxun` 数据库，给项目账号该库的权限。设置 `LINGXUN_DB_USER`、`LINGXUN_DB_PASSWORD`，按需覆写 `LINGXUN_DB_URL`。首次运行可用 `LINGXUN_STUDENT_PASSWORD` 和 `LINGXUN_REVIEWER_PASSWORD` 分别初始化学生、维护者账号，系统持久化其密码散列。生产 HTTPS 环境请设置 `LINGXUN_SECURE_COOKIE=true`；容器内监听需设置 `LINGXUN_BIND=0.0.0.0`。

```powershell
java -jar backend/target/lingxun-0.1.0.jar --spring.profiles.active=mysql
```

MySQL 环境从空数据开始。

已有 MySQL 数据库升级到本轮课程表版本时，`CREATE TABLE IF NOT EXISTS course` 不会自动补新字段，请先执行一次：

```sql
ALTER TABLE course
  ADD COLUMN week_pattern VARCHAR(8) NOT NULL DEFAULT 'EVERY';
```

`timetable_semester` 会由 `schema.sql` 自动创建。升级前已有的课程默认按每周处理。
